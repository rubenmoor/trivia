# Trivia

A family trivia party game, shown on the living-room TV. The family plays as one team against the gamemaster and needs 12 correct answers to win. Questions are in Spanish and are drafted, reviewed and illustrated with Claude; the gamemaster can review any of them again. Media (images, audio, video) comes from Wikimedia Commons.

It runs locally and offline: a small Python server (standard library only) serves a Svelte client and the playable question pool. Plans, decisions and open questions live in [`plans/`](plans/README.md).

## Layout

The repo is split into what ships and what doesn't ([`plans/19-repo-layout.md`](plans/19-repo-layout.md), D-35). `authoring/` may use code from `app/`, never the other way round.

| Path | Contents |
|---|---|
| `app/` | **The game, as it ships** |
| `app/server/` | Game server (static files, game API, media cache), game rules, question selection |
| `app/client/` | Game UI: Svelte 5 + Vite + TypeScript |
| `app/data/categories.json` | 24 broad categories and their 140 subcategories |
| `app/data/pool.json` | The playable pool: approved questions only, generated by `qgen export` (don't edit) |
| `authoring/` | **Tooling that never ships** |
| `authoring/data/questions.json` | The source pool: every question with its reviews, ratings and history |
| `authoring/tools/` | `qgen.py` (question pipeline), `media.py` (Commons search, contact sheets), `prompts/` |
| `authoring/server/`, `authoring/ui/` | Review tool, stats pages, printable joker cards |
| `authoring/RUNBOOK.md` | How an LLM makes a batch of questions: one command |
| `authoring/reports/` | One generated report per batch |
| `plans/` | Plans, decisions, open questions, backlog |
| `state/`, `media/`, `work/` | Game saves, media cache, pipeline work files (gitignored) |

## Setup

With Nix and [direnv](https://direnv.net/), run this once in the repo root; the dev shell then loads whenever you `cd` in:

```sh
direnv allow
```

Without direnv: `nix develop`. The dev shell has Node 22, Python 3, ImageMagick and Claude Code, plus the commands `trivia`, `trivia-authoring`, `qgen` and `trivia-media`, which run this checkout's scripts. Claude Code is the one unfree package the flake allows; log in once with `claude`.

Then:

```sh
npm install && npm run build      # both clients (npm workspaces: app/client, authoring/ui)
trivia-media sync --status approved   # download the media files (needs internet once)
trivia                            # http://127.0.0.1:8000/ — the game
```

## The game

| Command | What it does |
|---|---|
| `trivia` | Game server on http://127.0.0.1:8000/ (`--port`, `--host`). Same as `python3 app/server/main.py` |
| `npm run dev -w app/client` | Game UI with hot reload; forwards `/api` and `/media` to the game server, so run both |
| `npm run build -w app/client` | Build the game UI into `app/client/dist/` |
| `npm run check` | Type-check both clients |
| `nix build .#app` | The packaged game in `result/`: run `result/bin/trivia` |

`Esc` opens the admin menu (skip, undo, restart, fullscreen, volume; links to the review tool and stats when the authoring server runs). Game state and burned questions live in `state/game.sqlite` (delete it to reset everything). The packaged game keeps them in `$XDG_DATA_HOME/trivia/` instead; `TRIVIA_STATE` and `TRIVIA_MEDIA` override both.

## Authoring

| Command | What it does |
|---|---|
| `trivia-authoring` | Review tool and stats on http://127.0.0.1:8001/: the start page (what waits for you, batches, game readiness), `/review?batch=batch-4`, `/review/<id>`, `/stats/categories`, `/stats/subcategories`, `/stats/difficulty`, `/comodines` (printable joker cards) |
| `npm run dev -w authoring/ui` | Authoring UI with hot reload on port 5174 (run `trivia-authoring` too) |
| `qgen batch` | **Make a new batch of questions**, reviewed and illustrated: see [`authoring/RUNBOOK.md`](authoring/RUNBOOK.md) |
| `qgen validate` | Check the source pool and that `app/data/pool.json` is its current export |
| `qgen export` | Rewrite `app/data/pool.json` from the source pool (the authoring server does this after every change) |
| `qgen report [--player <name>] [--subcategories]` | Supply per level, difficulty and category |
| `trivia-media sync [--status approved] [--prune]` | Download picked media files that aren't cached yet. **Run before game night.** |
| `trivia-media fetch --batch <batch>` | Search Commons for candidates for questions without media |

The single pipeline steps (`qgen concepts`, `draft`, `rate`, `factcheck`, `revise`, `apply`, `merge`, `media`, `sheets`, `review`, `research`, `record`, `sync`, `batch-report`, and `import` for revising questions already in the pool) stay available for debugging; details in [`plans/07-question-generation.md`](plans/07-question-generation.md). Writing steps call `claude -p`; work files go to `work/<run>/`, and every step skips what's done, so a run can be resumed.

## Media

Media files are not in the repo. Each question stores the exact URL of its file (`file_url`); the media cache (`media/`) holds files named after those URLs. The game server downloads a missing file when it's first requested; `trivia-media sync` downloads them ahead of time. Credits (author, licence) are stored with each question and shown on screen.

## Dev environment

| Command | What it does |
|---|---|
| `nix develop` | Enter the dev shell without direnv |
| `nix flake update` | Update the pinned Node, Python, ImageMagick and Claude Code (`flake.lock`) |
| `direnv reload` | Reload the shell after editing `flake.nix` |

After changing `package-lock.json`, update `npmDepsHash` in `flake.nix` (`nix run nixpkgs#prefetch-npm-deps -- package-lock.json`).
